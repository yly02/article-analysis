# 编辑审校与发布门禁

修改文章连贯性、内容覆盖、审校调用或质量测试时读取。

## 默认调用链

```text
研究账本 → 完整草稿 → 主编完整阅读与补丁/完整修订 → 确定性合并 → 保守语言修复 → 本地质量门禁 → 证据规范化 → 渲染
```

默认是三次 LLM 调用。`--skip-editorial-review` 保留前两次，`--single-pass` 只保留写作调用。

## LLM 审校职责

编辑审校必须同时得到研究账本和完整草稿。单一输出模式默认返回：

- `quality_report`：连贯性、覆盖率、已修复缺口、已删除重复和剩余风险。
- `article_patch.set_fields`：修改过的顶层字段完整新值。
- `article_patch.section_updates`：按已有 section id 返回的实际章节修改。

多模式、适配器或 `DISTILL_REVIEW_OUTPUT_MODE=full` 返回完整 `revised_article`。补丁不得修改 `research_ledger` 或 `editorial_quality`，不得引用未知字段或章节；需要新增、删除或重排章节时必须用完整 `set_fields.sections`。结构无效或缺少补丁时自动发起一次完整修订回退，不能让错误补丁因草稿碰巧通过门禁而跳过语义主编审校。

两种输出协议都必须把报告中的“已修复”落实到补丁或完整修订稿，不能只给建议。输入中的数字口径、过程话术和语义覆盖阻断项必须修改对应公开字段；`quality_report` 本身不计为内容覆盖。

审校重点：

- `central_question` 是否由 `closing_answer` 回答。
- `narrative_plan` 是否形成内部阅读契约：开头承诺、正文主链和读后判断彼此一致，旁枝没有挤占中心。
- `reader_tension` 是否准确描述目标读者的真实判断困难而没有代编心理；`core_mechanism` 是否是一句清楚的因果解释，且所有章节都在证明、解释、限制或应用它。
- `opening_anchor` 是否来自已读取材料并在首屏真正落地；`reader_stake` 是否具体到判断、选择、成本或机会；`resonance_basis` 是否依靠真实处境而非抽象情绪；`stance` 是否有依据和改变条件。
- `title_contract` 是否把认知主体、唯一点击理由、读者承诺和证据边界对齐，标题是否在首屏兑现；`opening_sequence` 是否完成真实细节、矛盾转折和主体/机制揭示。
- `chapter_system` 是否选择了适合材料的主原型，每个正文 section 是否各有一个角色、理解缺口、新增推进和关键证据；相邻章节是否存在真实承接，而不是分类目录或整齐反问的集合。
- 标题是否从真实材料中提炼出足够的点击动机，并在首屏兑现，没有编造主体、动作、数字或结果。
- 新闻、案件和事件型材料是否在 `one_liner` 与第一节开头交代谁、何时、何地、做了什么、结果怎样；是否错误地用证据边界或抽象分析开场。
- 是否依次满足价值、可读性、共鸣：读者先有明确收获，再能轻松理解，最后能从真实处境中建立连接。
- 是否具备完整的灵魂、骨架、血肉、颜值：中心主旨和目标读者清楚，逻辑闭环且详略得当，素材扎实而表达准确生动，标题与排版真实放大内容。
- 是否真正面向聪明的 AI 初学者：首次术语有直观解释，事件或机制无需外部背景即可复述，领域意义清楚，又没有以“科普”为名删除重要条件。
- 是否形成可复用母稿：一句话主旨、连续主线、可独立提取的章节观点、可视化关系和有记忆点的结论均清楚；正文仍是自然文章，不是视频提纲。
- `distinctive_insight` 是否由材料中的机制、矛盾、取舍或后果推出，并在正文中得到论证；通用 AI 口号不能通过审校。
- `category_tags` 是否先概括中心判断，再覆盖关键机制或现实后果；是否误把发布方名称、高频词和“AI、基础设施、企业 AI”等宽泛大类当成主题提炼。
- 专有名词是否保留官方或原始拼写；主标题、章节标题、图表标题和表头是否出现了翻译括注或编辑自创的中文别称；导语或正文中确有稳定常用译名且会帮助理解的陌生英文术语，首次出现是否已采用 `原名（常用中文名）`，而不是只做名词解释脚标；同时避免重复括注、无依据音译，以及对人名、品牌、产品、代码、模型编号、文件名和大众熟悉缩写的机械翻译。
- 正文是否按因果、递进、转折或问题回答推进。
- `importance=high` 的 claim 是否写入，或在 `omitted_claims` 中给出具体理由。
- 限制条件、反例和 unknowns 是否被保留，而不是为了流畅被删掉。
- full、onepager、cards 的事实、数字和结论强度是否一致。
- 是否用多个相似段落或卡片重复同一结论凑数量。
- 是否逐句检查了主谓宾、修饰关系、固定搭配、指代、成分残缺和句式杂糅，并实际改写问题句。标题、表格标题、表头和压缩短句同样需要审校。
- 中文语病审校是否依次完成主干、横向搭配、纵向照应、结构完整、否定还原、歧义、数量范围和标点检查；是否把明确病句、依赖语境和纯文风建议分开，避免为了显得严格而强行挑错。
- 修改是否遵守最小改动，并保持事实、主体、因果、时间、程度、数字和条件范围不变；歧义无法由材料消除时是否保留风险而非猜测原意。
- 关键解释章节是否用具体问题建立阅读目标，并在正文前 1-2 句直接回答；是否存在问题超出证据、答案延迟、答非所问或连续堆叠问句。
- 非空 `sections[].transition_hook` 是否来自本节已经建立的信息，并由下一节立即回答；下一标题可以压缩重述疑问，但不得逐字复制，不能出现空悬念、句式重复或最后一节悬而未决。
- 每节是否只完成一个主要任务并增加新事实、新区别、新机制或新后果；具体证据是否先于抽象解释出现。
- 相邻章节是否机械重复同一种开场动作和内部骨架。问答、事件、结果、数据、例子、冲突与判断应按材料自然轮换，不能为了活泼虚构场景。
- 冷读时不依赖标题、摘要、提纲和来源说明，正文能否独立说清中心、关键支撑和最终完成的结果或选择；删除不削弱论证的段落，最后两段删后更有力时提前结束。
- 人味终审是否清理了段段金句、匀速句长、固定连接词、虚构反问、假脆弱、假故事和无必要升华；是否避免照搬个人作者的口癖、粗口、网络梗和虚构第一人称体验。
- 背景知识是否只在主线需要时自然出现；是否存在脱离叙事的知识倾倒、单独“科普一下”或为了显得有深度而强接文化与哲学。

## 确定性门禁

`editorial_quality.py` 不判断事实真伪，只检查可重复验证的不变量：

- full 至少 3 个标题与正文均非空的段落。
- full 的一分钟导览必须恰好 3 条、合计不超过 180 字；单条超过 70 字时警告。
- onepager 至少 3 个有效小节且有 lead。
- cards 至少 4 张有效内容卡且有 cover hook；少于 6 张会警告。
- 同一输出内相似度达到阈值的段落或卡片视为重复并阻止发布。
- 新生成的 full 必须包含完整 `narrative_plan`。
- 新增的人味策划字段先作为兼容性指标和 warning，不对旧 JSON 设 blocker；是否真实、自然仍由 LLM 主编结合材料判断，不能用正则冒充文学审校。
- `title_contract`、`opening_sequence` 与 `chapter_system` 同样先作为兼容性指标和 warning；确定性门禁只检查字段和章节 id 是否对齐，不机械判断标题冲击力、案例代入感或章节文学质量。
- 研究账本中的 high claim 必须出现在 `covered_claim_ids`，或在 `omitted_claims` 中同时提供 ID 和具体 reason。
- 对未舍弃的 high claim 执行发布内容语义覆盖检查。full、onepager、cards 分别建立公开语料，只统计读者会看到的正文、实验、案例和视觉组件；`fact_check`、`research_ledger`、`source_notes` 不参与匹配。
- 语义覆盖报告保存到 `metrics.semantic_claim_coverage`，逐条给出 `matched_terms`、`missing_terms`、分句结果和匹配比例；`semantically_missing_high_claim_ids` 汇总实际漏写的主张。数字、百分比、型号和专有名词必须精确出现，常见自然同义表达会先做保守归一化。
- `interactive_compare` 至少包含两个有名称的候选和两个模式；每个 `selected_index` 必须指向现有候选，并提供机制示意边界。无效结构或锚点在严格发布时阻止渲染。
- `scenario_calculator` 至少包含两个有指标的对象、合法滑块、计算基数、来源媒体和边界说明；来源数值与读者假设必须分开。无效结构或锚点在严格发布时阻止渲染。
- `capacity_curve` 只接受3至5个位置严格递增的定性状态，每项含阶段、解释和固定语义色；caption 必须明确具体转折点会随条件变化且不是通用预测器。无效结构或锚点在严格发布时阻止渲染。
- `cost_ledger` 只接受1至4个登记项目和2至6个唯一情景；每个 `included` 只能引用登记项目，并写清判断、原因和统一口径边界。无效结构或锚点在严格发布时阻止渲染。
- `strategy_tabs` 只接受2至6个平行方案；每项必须写清作用对象、机制、预期效果、待补条件和语义色，并提供统一阅读边界。它不能替代时间流程或精确数值表；无效结构或锚点在严格发布时阻止渲染。
- `rank_bars` 只接受1至4个分组，每组2至18项同单位、同正负方向且按绝对值降序的数值；显示值必须保留原值，boundary 说明条长口径和不能推出的结论。无效结构或锚点在严格发布时阻止渲染。
- `funnel_flow` 只接受2至5道真实资格关口，必须含入口、每关说明和 caption；显式宽度需逐级递减，caption 必须说明没有真实转化率时宽度只表示收窄。无效结构或锚点在严格发布时阻止渲染。
- `delta_table` 只接受2至8个同口径前后变化项；每项必须有旧值、新值、变化、方向和固定语义色，并提供统一 boundary。无效结构或锚点在严格发布时阻止渲染。
- `status_matrix` 只接受2至6个维度和2至8个对象；每行 cells 数量必须等于 columns，每格都有文字状态和固定语义色，同时提供 caption 与 boundary。无效结构或锚点在严格发布时阻止渲染。
- `decision_table` 只接受2至8条条件规则；每条必须分开 condition、result、action 和语义色，并提供适用范围 boundary。无效结构或锚点在严格发布时阻止渲染。
- `flow.presentation=stepper` 只接受3至7个含阶段名、标题和说明的完整步骤，并提供 caption；普通 static 流程仍至少有两个有效步骤。无效结构或 stepper 锚点在严格发布时阻止渲染。
- `timeline.presentation=scrubber` 只接受3至8个含时间、标题和说明的完整节点，并提供 caption；普通 static 时间线至少有两个完整节点。无效结构或 scrubber 锚点在严格发布时阻止渲染。
- high 且 `claim_kind=metric` 的主张必须由 `number_stories` 覆盖。完整性同时检查主数字、单位、分母、适用范围、时间、对照或变化、边界、来源、claim id 和章节锚点；“未知”等占位内容不算完整。不完整 high metric 阻止严格发布，普通数字降级为 prose 并产生警告。
- `evidence_gallery` 只允许已登记媒体，不允许重复 URL。规范化器自动纳入正文来源媒体和数字故事引用的证据图，发布门禁检查注册状态与去重结果。
- 原始媒体登记中的每个 `asset_role=demo|hero` 视频都必须与成品逐个对账：进入 `source_media`，或进入 `media_omissions` 并给出具体理由。未采用且未说明、引用未登记素材、理由空泛、重复记录或同一视频既采用又省略，都会阻止严格发布。视频不是数量配额；采用多段时按各自问题分散到相关章节。
- 扫描标题、正文、速览、表格、一页纸和卡片中的高置信语病，并返回 JSON 字段路径。重复标点和明确的固定搭配错误会自动修复；无法在不改变含义的前提下修复的问题会阻止严格发布。
- 确定性扫描补充明确赘余、固定句式杂糅、否定失当、关联词混用、数量范围和部分标点问题；易受语境影响的“通过……使……、是否/能否、由于……因此……”不做机械判错。
- 对完整正文额外输出保守的编辑信号：替读者预设想法、仪式化深刻表达、多个章节句长过于均匀、单节连续抛出三个以上问题。这些信号只产生警告，由主编结合语境判断，不做机械改写。
- 对公开标题、小标题和视觉卡片标题额外扫描“如何被接住、被托住、被兜住、跑通闭环”等抽象动作。命中时只产生文风警告，提示主编补回具体主体和真实动作，不把它误判成语病或机械替换。

语言门禁不会读取或改写 `research_ledger`、逐字引文、URL、代码和图片元数据。自动修复记录保存在 `editorial_quality.language_fixes`，便于回看具体改动。

生成后同时审计草稿和修订稿。修订稿质量更差时保留草稿；两者都不合格时抛出明确错误，不渲染半成品。

已有旧 JSON 通过 `--render` 时，缺少 `narrative_plan` 和新增的语义覆盖只产生兼容性警告；空段、重复段和目标输出缺失仍会阻止渲染。新生成内容使用严格语义门禁。

## 非目标

- 字符串相似度不能代替人工文学判断。
- 本地语言规则只能兜住高置信模式，不能替代主编对语义、节奏和文风的判断。自动修复必须保持事实含义不变；有歧义时只报告，不猜测作者意图。
- 确定性语义覆盖是保守的词义锚点检查，只用于发现明显漏写，不能证明模型真正理解了原文，也不能替代主编审校。完整函数签名、中文百分数与阿拉伯数字、以及常见中英术语表达会先做等价归一；数字和代码锚点仍必须真实出现在发布内容中。
- 没有真实 LLM 调用时，只能证明流程和门禁逻辑有效，不能声称实际文章质量已经得到线上验证。
