# 文章视觉选择

视觉的任务是减少理解成本。先写出读者需要回答的问题，再识别材料中的真实关系，最后选择组件。不要先挑样式再往里塞内容。

| 内容关系 | 优先组件 | 适用条件 | 不该使用时 |
|---|---|---|---|
| 已登记音频或视频证据 | `listening_cards` / `source_media` | 读者需要实际听见或看见差异 | 没有真实媒体，或媒体只是装饰 |
| 两个以上平级对象的异同 | `compare_table` | `paired` 适合长解释，`matrix` 适合固定字段查阅，`stacked` 适合逐主题阅读 | 对象存在上下层依赖或时间先后 |
| 同一指标的旧版/新版或调整前后变化 | `delta_table` | 旧值、新值和变化值来自相同口径，方向明确 | 两个对象只是平级比较，或变化无法可靠计算 |
| 多个对象跨多个固定维度的支持状态 | `status_matrix` | 2至6个维度、2至8个对象，状态定义一致 | 需要比较精确性能或只有一条状态 |
| 条件决定结果，并对应可执行行动 | `decision_table` | 条件和结果来自材料，行动明确是编辑建议 | 普通步骤、无条件建议或静态异同 |
| 同一口径下多个数值的大小排序 | `rank_bars` | 单位、总体、时间一致，排名本身是阅读任务 | 需要比较两套方案，或不同指标不能共用刻度 |
| 同一批对象的多个数值问题 | `metric_bars` | 每次切换一个口径，并保留原值、单位和优势方向 | 指标口径不能比较，或只有一个数字 |
| 架构、能力、组织或上下游层级 | `layer_stack` | 2至7层，上层确实依赖或建立在下层之上 | 只是并列清单、时间线或动作流程 |
| 有明确先后动作或因果推进 | `flow` | 短流程用 `static`；3至7个解释较长的阶段可用 `stepper` | 只有日期演进，或各项没有先后 |
| 资格判断让候选范围逐关收窄 | `funnel_flow` | 2至5道真实关口，每关会淘汰一部分对象 | 只有动作先后，没有资格淘汰关系 |
| 日期和阶段演进 | `timeline` | 日期清单用 `static`；3至8个有独立解释的节点可用 `scrubber` | 时间只是附属信息 |
| 条件切换会改变结果 | `interactive_compare` | 候选和模式有材料依据，切换本身能解释机制 | 只是为了增加点击操作 |
| 来源基数加读者假设 | `scenario_calculator` | 基数、公式和假设边界都清楚 | 缺少可靠基数或跨口径硬算 |
| 连续变量出现拐点、U形或倒U形 | `capacity_curve` | 材料支持方向变化，读者需要理解“更强未必更好” | 只有两个离散对象，或需要展示精确实验数值 |
| 多个成本、资源或责任项按情景计入或排除 | `cost_ledger` | 计入口径本身会改变结论 | 读者的任务是逐格查询精确数字 |
| 多个平行策略分别改变不同对象、机制和限制 | `strategy_tabs` | 读者需要逐项查看“改哪里、怎么改、还缺什么” | 方案有严格时间先后，或需要逐格查数 |
| 1至3个口径完整的主数字 | `stat` 或一张公开 `number_story` | 数字本身承担论证任务 | 数字已在其他视觉和正文完整出现 |
| 官方图表、截图或原始证据 | `source_media` / `evidence_gallery` | 图本身能让读者核对关键主张 | 只是照搬装饰图或重复正文 |
| 空间、材质、尺度或氛围本身承担解释 | 审核后的 AI 位图 | 现有来源媒体和代码化组件都无法清楚表达 | 流程、层级、时间、对比或因果关系可直接代码化 |

## 版面约束

- 同一章节通常只有一个主视觉；来源媒体可以作为证据补充。
- 原文自带的官方演示视频优先于 AI 概念图。先从原始 HTML、自定义媒体组件和懒加载属性登记真实视频，再按它回答的问题放到相关章节；不把多段演示集中堆在文末。
- “原网页有视频”不是采用理由。只有能展示产品操作、实验过程、前后差异、人物关键表述或机制变化，且正文和静态图无法等价替代时才发布。循环口号、气氛动画、品牌片头和纯装饰首屏视频默认省略，并在 `media_omissions` 写明理由。
- JS 渲染页使用浏览器降级提取时，先锁定目标文章根节点，再分别统计内容图片、视频、音频和海报；正文文本提取成功不代表媒体提取成功。渲染后重新统计成品媒体，并与目标文章清单及 `Article.media_assets` 逐项对账。首屏叙事视频若承担开篇语境，可以放在首章之后并用图注说明其叙事作用；若不采用，必须记录具体舍弃理由。
- `flow`、`funnel_flow`、`rank_bars`、`delta_table`、`status_matrix`、`decision_table`、`layer_stack`、`timeline`、`compare_table` 等代码化关系图优先于 AI 位图。不得从这些组件自动回退生成内容重复的概念图。
- AI 位图只有在空间、材质、尺度或氛围能显著降低理解成本时才使用；发布前至少比较 2 个候选，出现水彩纸张、手绘草图、通用图标拼贴、模板信息图或廉价 3D 素材感即淘汰。
- 视觉必须比相邻正文更快回答一个问题，不能原样复述段落。
- 不连续使用三个相同结构。多样性来自文章确实包含不同关系，不设组件数量配额。
- `matrix` 超过6行、4列或24个单元格时，只有逐格查数是核心任务才保留；否则按问题拆分或改为切换、分层。
- 同一组参数只回答一个数值口径时，若读者需要看固定字段就用六项以内的 `compare_table.matrix`；若大小与排序本身是重点就用 `rank_bars`，正负参数分组切换，组内按绝对值降序。只有读者确实需要在至少两种合法指标或口径之间切换，且每种口径都有完整双方案对照项时，才使用 `metric_bars`；不能为了显得可交互，把单组参数伪装成双方案比较。
- `funnel_flow` 的逐级变窄只表达资格范围收窄，不代表精确转化率。没有来源支持的数量、比例或淘汰率不得从形状推导；普通步骤、日期或层级分别使用 `flow`、`timeline`、`layer_stack`。
- `delta_table` 的变化值必须由材料直接提供，或从同单位、同总体、同时间口径的旧值与新值可靠计算；只知道“更好”“更快”时不能伪造具体变化。没有版本或时间关系时改用 `compare_table`。
- `status_matrix` 的状态词和颜色在同一张表中必须保持同义，例如绿色始终表示已支持或明确满足，琥珀色始终表示有限或有条件，红色只表示材料确认的不支持或失败；颜色不能替代文字，也不能把定性状态冒充性能得分。
- `decision_table` 中 condition 与 result 是来源规则，action 是面向读者的编辑建议。三列必须分清事实层与建议层；普通流程用 `flow`，无条件建议用 `action_card`。
- 交互只在隐藏次要信息、切换问题或改变条件能降低理解成本时使用。没有信息增益就保持静态。
- 优先考虑能让读者主动验证文章判断的交互：变量移动看结果用 `capacity_curve` 或 `scenario_calculator`，模式切换看选择变化用 `interactive_compare`，成本口径切换用 `cost_ledger`，复杂阶段逐步理解用 `flow.stepper`，时间节点拖动查看用 `timeline.scrubber`。操作前后若只是同一句话换位置，就不是有效交互。
- `flow.stepper` 每次聚焦一个复杂阶段，但无 JavaScript 与 Markdown 必须展开全部步骤；关键事实不能只存在于默认隐藏的面板。`timeline.scrubber` 同样保留静态节点清单，时间顺序和解释不能依赖脚本才能读取。
- 定性曲线只说明方向和拐点逻辑，不输出未经来源核验的精确损失、概率或最佳点；需要精确计算时改用有来源基数和公式的 `scenario_calculator`。
- 成本账本优先替代不需要逐格查数的大表格。每种口径同时显示“计入什么、判断是什么、为什么”，不能只换颜色不换信息。
- 结尾的2至4个决策问题按阅读顺序纵向展示，不做横向并列大卡；已能完成收束时删除重复行动清单。
- 颜色保持语义一致：核心信息和对照方案用蓝色，主方案、正向结果和明确进展用绿色，限制、条件和待确认项用琥珀色，红色只用于材料明确支持的风险、失败或损失。所有 `tone` 和 `column_roles` 使用同一组角色；不确定时保持中性色，不制造彩虹表格。
- 窄屏保证自然换行，不让表格、播放器、按钮或标签撑破正文宽度。
