# 延伸检索与媒体中文化

在处理新文章、原页存在外链或用户要求补充素材时读取。本流程的目标不是堆链接，而是让正文获得原文之外的实现细节、独立证据和真正有解释力的媒体。

## 四段链路

1. **主题扩展检索**：从文章的主体、产品/模型名、关键主张、论文标题、作者和独特术语生成查询。
2. **实际读取与分级**：打开候选页并读取正文；未读取的搜索结果只能是线索，不能进入证据或延伸阅读。
3. **媒体价值筛选**：逐个判断视频、图片、图表、截图和音频是否给正文增加可见或可听信息。
4. **中文化再表达**：对采用素材补自然中文标题、图注和观看重点；能可靠还原的英文图表优先重构为中文 HTML 组件。

## 默认搜索面

浏览器、搜索工具或站内搜索可用时，默认围绕中心问题补充 2-5 个高价值来源，不追求固定数量。并行检查：

- `主体/产品 + 官方公告/文档/model card/repository/paper`
- `论文标题/DOI/arXiv id + 作者或项目主页`
- `关键数字或结论 + dataset/method/appendix`
- `中心主张 + independent study/review/replication/critique`
- `人物/产品 + demo/interview/keynote/video`
- 图表 caption、来源标签或截图内机构名对应的上游页面

优先级从高到低：官方上游资料与原始论文、代码仓库和数据集；独立研究或可靠复测；有编辑责任的深度报道；聚合页和对标文章仅作线索。对标站的图片、视频或链接必须追到原始发布者或明确标注为加工版，不能把对标站变成事实来源。

原文明确链接到同一发布方的案例复盘、设计说明或实现细节时，按主题重合度优先读取；组织首页、标签页、作者页和通用协议页只作为导航，不得挤占有限的补充来源名额。发现官方 GitHub 仓库后，除了读取仓库首页，还要执行受限源码深读，优先选择会改变读者判断的权限、审批、策略、配额、失败处理和核心算法文件。

主题搜索不是事实核验的同义词。发布方模型卡、仓库和公告属于 `official`，只能补细节；只有独立于发布方且实际读取的研究或复测才能标为 `independent` 并支持 `cross_checked`。

## 自动动态发现与浏览器后备

远程网页默认在静态抓取后运行 Playwright，滚动页面并收集 JavaScript 渲染后的 `img`、`video`、`audio`、媒体 `source`、常见视频 iframe、CSS `background-image` 和媒体网络请求。结果直接合并进 `Article.media_assets`，不需要用户额外传参数。首次运行优先使用系统 Chrome、Edge 或 Chromium，没有时自动安装 Playwright Chromium。

动态发现失败不能伪装成“页面没有媒体”。CLI 默认停止并输出失败原因。只有用户明确接受媒体可能遗漏时才使用 `--no-dynamic-media`。如果站点对无会话浏览器返回 403，而 Codex Browser 能打开页面，代理应自动完成浏览器后备检查：导出结构化素材并加入下列标记，再通过 `--page-assets` 重跑：

```json
{
  "media_discovery": {
    "status": "completed",
    "method": "codex_browser",
    "page_url": "https://example.org/article"
  }
}
```

带有完成标记的浏览器清单会替代本次无会话 Playwright 检查；没有完成标记的普通素材 JSON 只负责补充，不会让动态完整性检查提前通过。

## 浏览器结果回灌

网页受登录态、反爬或特殊播放器影响，或者主题搜索在浏览器中完成时，把结构化结果保存为 JSON，并通过：

```bash
python <skill-root>/scripts/run.py <URL> \
  --page-assets page-assets.json --both -o article
```

支持的顶层集合：

- `links`、`sources`、`research_sources`、`related_articles`
- `images`、`videos`、`audio`、`media`、`media_assets`

最小示例：

```json
{
  "research_sources": [
    {"url": "https://example.org/paper", "title": "材料标题", "source_type": "independent"}
  ],
  "videos": [
    {
      "id": "media-demo-1",
      "src": "https://cdn.example.org/demo.mp4",
      "poster": "https://cdn.example.org/poster.jpg",
      "source_page": "https://example.org/official-post",
      "role": "demo",
      "language": "en",
      "caption": "中文图注",
      "reader_note": "观看时重点留意什么",
      "upstream_sources": ["https://example.org/original-video"]
    }
  ]
}
```

回灌只完成登记与去重，不代表自动采用。登记链接仍需成功抓取才可进入证据和 `further_reading`；媒体仍需经过价值筛选和发布门禁。

## 媒体价值判断

采用素材至少满足一项：

- 展示产品或模型的真实操作过程，而不是品牌片头。
- 展示实验设置、样本、前后差异、失败模式或机制变化。
- 保存人物关键表述，且措辞本身影响理解或判断。
- 提供正文难以替代的原始图表、界面状态或实物尺度。
- 音频能让读者实际听见节奏、音色、语言、结构或编辑变化。

默认省略：气氛视频、口号动画、Logo/头像/图标、重复长图、与正文同义的宣传片、低清缩略图、没有上游出处的搬运素材，以及仅为“页面丰富”而加入的图片。

同一章节通常只有一个承担解释任务的主视觉。来源媒体可作为证据补充，但不能与紧邻组件重复表达同一信息。长图优先拆成局部读图或重构组件；两个相邻素材回答同一问题时只留信息密度更高的一项。

## 中文化再表达

- `caption` 写成自然中文，说明素材展示了什么，不逐字翻译文件名。
- 外语媒体填写 `language`，并用 `reader_note` 写清“看什么/听什么，以及它与正文哪项判断有关”。
- `translation_note` 只描述真实完成的加工，如“根据官方英文标题译写”“视频自带中文字幕”“编辑重构为中文交互图”。没有生成字幕就不能声称有字幕。
- 人名、品牌、模型、论文简称、代码和文件名保留官方拼写；稳定常用中文名只在正文首次出现时括注。
- 英文图表的数据、坐标、分组和单位能可靠读取时，优先重构为适合关系的中文 HTML 组件，并把原图留在证据图库；不能可靠读取时保留原图，加中文读图提示，不猜数字。
- 外语视频无法完整核对字幕时，只概括已确认的画面与公开表述，不制作伪逐字稿。

## 发布前自检

- 实际读取的补充来源为 1-5 条；`further_reading` 使用准确中文标题，并保留必要专名。
- 每个采用媒体都能回答一个明确读者问题；去掉后若正文理解不受影响，应考虑省略。
- 每个 `demo`/`hero` 视频都已采用或进入 `media_omissions`，理由具体。
- 外语媒体同时具有中文 `caption` 和中文 `reader_note`。
- 素材 URL、上游来源、语言、加工说明和段落锚点可追溯；不把媒体展示当作独立性能证据。
- 浏览器最终核对播放器/图片真实可见、URL 正确、窄屏不溢出，页面没有因重复媒体被无意义拉长。
- HTML 写盘前再次解析最终成品。每个已采用的来源媒体必须存在对应 `data-media-id`，实际 `img/video/audio/iframe/source` URL 必须与注册表一致；试听音频也必须存在真实 `<audio>` 节点。对账失败直接阻止交付，而不是留下半成品。
