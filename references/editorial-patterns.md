# 对标文章提炼出的编辑模式

生成完整长文、设计章节或做成稿后对比时读取。本规则来自历次独立成稿后的对标复盘，只吸收可复用的编辑能力；对标文章不是事实来源，也不能参与首稿补写。

## 四项可复用优势

### 1. 标题先给点击理由

强标题不是把语气放大，而是让读者一眼看到“谁做了什么，反常在哪里，读完能知道什么”。内部用 `title_contract` 检查四件事：

- `recognition_anchor`：只填写一个读者认识、且必须逐字进入标题前半句的公司、产品或人物常用名称；不要写解释性长句。没有高认知主体时才使用最具体的事件对象或结果。陌生项目代号若有知名归属方，必须让归属方先出现，不能让代号单独承担标题认知。
- `click_reason`：只选一个最有张力的事实，可来自冲突、反差、意外后果、关键数字或现实问题。
- `reader_promise`：标题承诺文章会解释哪件事，不能只制造情绪。
- `evidence_guardrail`：写清不能越过的事实边界，尤其防止把相关写成因果、把平台报告写成 AI 主动报警、把设备特征采集写成监控个人。

标题通常优先采用“高认知主体 + 反常动作/结果 + 明确对象”或“具体结果 + 为什么会发生”两类结构。数字只有同时具备分母、时间和口径时才进入标题。标题可以有冲击力，但首屏必须立即兑现并补足必要限定。

参数、概率和评分系数进入标题时，必须保留它们在原始系统中的语义。代码写的是“动作预测权重 20”，标题就写“权重 20”，不能为了更像新闻而改成“一次动作值 20 分”；正文首屏还要说明它乘的是预测值、真实次数还是其他量。数字标题既要具体，也不能先制造一个错误心智模型，再依赖后文纠正。

### 2. 用真实例子完成进入

开头不是先解释概念，而是用材料里最容易理解的真实细节让事情发生。优先级通常是：人物动作或事件结果 > 反常失败模式 > 大小悬殊的案例组合 > 有明确口径的数字 > 直接陈述事实。

`opening_sequence` 固定三个动作：

1. `scene`：用一到三个真实细节建立画面或处境；
2. `turn`：指出这些细节共同暴露的矛盾、反差或问题；
3. `reveal`：交代主体、时间、动作和核心机制，并把问题交给正文。

例子不是装饰。它必须同时承担背景、矛盾或机制入口中的至少一项任务。不能使用对标文章新增的例子，不能虚构读者经历，也不能把刺激性细节写得比证据更确定。例子移到开头后，后文只增加解释、证据或后果，不成组重播。

研究和技术文章没有人物事件时，先提出材料确实能回答的现实决策，例如“预算固定时该把算力给教师还是学生”“更强的模型是否一定教得更好”。首屏先让读者明白选择及代价，再在第二层解释术语、模型参数和实验规模。不能一上来连续堆论文名称、参数量和跑分，让读者还没建立问题就先承担理解成本。

### 3. 章节组成一套推进系统

先根据材料选择一种主原型，再用 `chapter_system` 规划章节。原型不是固定模板，可以合并、删减或局部借用，但不能把互不相干的原型拼成目录。

- **事件/案件**：事情发生 -> 机构或人物怎样行动 -> 为什么会这样 -> 谁得到好处、谁承担成本 -> 仍未知什么 -> 应怎样判断。
- **调查/异常**：怪事出现 -> 排除常见解释 -> 抓到关键线索 -> 机制怎样运作 -> 能说明与不能说明什么 -> 用户选择。
- **产品/发布**：旧问题或失败模式 -> 新能力解决什么 -> 核心机制 -> 真实演示或证据 -> 接入、成本与许可证 -> 适合谁。
- **论文/研究**：具体结果或安全案例 -> 核心机制 -> 实验怎样做 -> 关键差异与反例 -> 现实外推边界 -> 行动或治理。
- **多图/多主题**：先给统一观察框架 -> 按资本、建设、劳动、使用等有因果或层级关系的分组展开 -> 每组保留一个主数字和时间变化 -> 最后回答这些组为何属于同一变化。
- **机制解释**：读者熟悉的现象 -> 核心部件 -> 动作顺序 -> 切换条件或失败点 -> 现实影响 -> 使用判断。

工程实现超过五步时，先寻找读者真正需要记住的三至四个决策关口，再把详细步骤放进关口内部。关口必须对应真实的职责分离、进入条件或结果变化，不能为了好记任意合并；例如“候选资格 -> 预测排序 -> 展示资格”可以作为上层记忆框架，七步流水线继续作为证据细节保留。

每个章节计划至少包含：

- `section_id`：对应成稿章节；
- `role`：进入、发现、解释、举证、转折、后果、选择或收束；
- `reader_need`：读者到这里必须解决的一个理解缺口，不要求都写成问句；
- `advance`：本节相对上一节新增的事实、区别、机制、后果或选择；
- `evidence`：支撑本节推进的关键材料；
- `handoff`：下一节为什么必须接着出现，没有自然承接时留空。

章节标题要准确标记推进动作。问题标题用于读者确实会问且本节能立即回答的问题；事件、结果和判断也可以直接做标题。避免“背景、分析、影响、总结”这类只说明文档类别的标题，也避免七节都用相同反问。

### 4. 证据和视觉跟着论点走

对标文章做得好的地方，常常不是图更多，而是图、引用、案例与当前问题同时出现：

- 原始图表放在它直接支撑的结论之后，并说明“看什么、能说明什么、不能说明什么”。
- 静态原图存在可靠对象和计算关系时，可转成交互卡；原图仍保留在证据图库。
- 产品和音乐文章让真实演示可看、可听，并告诉读者具体观察什么，不把官方精选样例写成普遍质量。
- 正反观点有真实引文时，可用短引用形成现场冲突；没有逐字材料就做证据重建，不编对话。
- 图表型文章采用“正文精选核心图 + 折叠完整证据图库”，不在全塞和全删之间二选一。

## 成稿后对标边界

- 必须先依据原始材料独立研究、成稿并通过门禁，再读取对标文章。
- 对标只检查标题、进入方式、章节推进、解释密度、视觉组织和发布体验。
- 对标中出现而原始研究链没有的事实，只能作为待核查线索；独立抓取并登记前不得补进正文。
- 对标文章中的权重、规则数量、版本变化和“当前值”必须回到带提交或日期的原始快照核对。事实成立但已经过期时标明版本；计数不符时以可复查的代码清单为准，不因对标文章更好读而沿用。
- 不吸收未经证实的极限词、强因果、虚构场景、来源不明数字和为了剧情制造的时间关系。
- 站内导航、推荐、订阅、收藏、分享和会员路径属于发布壳层，不继续塞进文章写作 Prompt。
- 对标是内部质量流程，默认自动执行，不在每次交付中重复向用户解释以上边界。只有发现新增事实线索、事实冲突、夸大或来源风险时才显式报告。
- 对标发现的优势不能只修当前成品。确认可复用后，必须同步到相应参考规则；涉及新数据结构、视觉行为或可确定校验时，还要进入生成提示、HTML/Markdown 渲染器与发布门禁。

参数型文章必须把“读者能采取的选择”与“来源直接给出的事实”分开：先说明参数反映的系统方向，再把它转成内容、产品或运营判断，并明确这不是效果保证。行动部分优先回答“目标是什么、哪一道机制与它相关、怎样判断是否走错路径”，不要把参数表改写成万能攻略。

## 结尾收束

结尾先回答开头问题，再把复杂判断压缩为2至4个有顺序的问题：先问目标或约束，再问关键匹配或证据，最后问真实成本、风险或行动条件。问题沿阅读方向纵向排列，每一问都必须能由正文材料回答，不能用“未来如何”“值得关注什么”等空问题充数。

三问或四问已经让读者完成判断时，删除内容重复的行动卡、带走清单和第二段总结。结尾不是再讲一遍全文，而是让读者把本文方法带到下一个真实选择里。

## 终审

- 标题是否有一个清楚点击理由，并在首屏兑现，而不是靠形容词放大？
- 开头例子是否同时建立处境并引出核心机制，还是可以删掉的装饰？
- 只读章节标题，能否看见一条从进入到回答的推进链？
- 每节是否解决一个新的理解缺口，并把下一节变得必要？
- 原图、案例、引用、表格和互动是否出现在它们真正支撑的论点旁边？
- 删掉任何一节后是否会失去一种独立推进；不会就应合并或删除。
